# 02. Meta Muse Code
### Code Implementation Engineer, AST Analysis, and Self-Healing Loop

---

## 1. What Is Meta Muse Code?
**Meta Muse Code** (together with the Code Llama family and Llama 3 code variants) is Meta's model specialized in **formal programming-language grammar, syntactic reasoning, and code refactoring**. It produces minimal boilerplate, deeply understands static types, and absorbs compiler error contexts to perform precise surgery on source code.

---

## 2. Specific Role in FlutterGuard-AI
In FlutterGuard-AI, Muse Code acts in **Phase 2: Implementation and Self-Healing**:
1. **Turning Tests GREEN:** Reads the contract and the failing tests generated by Muse Spark, then writes the strictly necessary implementation in `lib/` to make the suite pass.
2. **Respecting Architectural Guardrails:** Follows the layer separation rigorously (e.g. Presentation, Domain, Data) without introducing forbidden coupling.
3. **Self-Healing via Canonical Recipes (*Self-Healing Loop*):**
   * When the local AST analysis engine (`dart analyze` or a Dart AST Visitor) flags a violation (e.g. creating a `ScrollController` inside `build()` without `dispose()`), FlutterGuard-AI injects the offending snippet together with the canonical recipe from the catalog (`../../docs/Methodology/CanonicalRecipesCatalog.md`).
   * Muse Code receives the *Before / After* pattern and refactors the code in a single inference turn.

---

## 3. Input and Output Format (I/O)

### Self-Healing Payload (AST Refactor Prompt):
```text
[SYSTEM]: You are the FlutterGuard-AI Implementation Engineer.
[AST ERROR DETECTED]: The 'ProductListWidget' widget instantiates 'ScrollController' inside build(). This leaks memory and loses state on rebuild.
[CANONICAL FIX RECIPE]:
  - Migrate the widget to StatefulWidget (or use a Hook / external-layer Controller).
  - Initialize the controller in initState().
  - Always call controller.dispose() in dispose().
[CURRENT CODE]:
{code_with_failure}
[TASK]: Return only the fixed Dart class, following the canonical recipe 100%.
```

## 4. Hands-On Study Roadmap

1. **Using the Dart SDK `analyzer` Package:**
   * Learn to navigate the AST (`CompilationUnit`, `ClassDeclaration`, `MethodDeclaration`, `AstVisitor`).
   * This lets FlutterGuard extract the exact failing node and send a microscopic context to Muse Code, saving tokens and avoiding hallucinations.
2. **Red/Green Feedback Cycle:**
   * Train the local `flutter test --reporter json` command to capture the failure message in machine-readable form and feed it to the model.
3. **Studying the Canonical Recipes Catalog:**
   * Review the project's [CanonicalRecipesCatalog.md](../../docs/Methodology/CanonicalRecipesCatalog.md) to map the top 10 Flutter anti-patterns the model must fix.
